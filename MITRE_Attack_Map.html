// WHAT IS MITRE ATT&CK?
MITRE ATT&CK is a globally accessible knowledge base of adversary tactics and techniques based on real-world observations. Think of it as a universal language for describing how cyberattacks happen.

Tactic = the attacker's GOAL at that phase. ("Why are they doing this?")
Technique = HOW they achieve that goal. ("What exactly did they do?")
Procedure = the specific tool or command used. ("DarkSide ransomware specifically...")

The matrix has 14 Tactics (columns) and hundreds of Techniques underneath. When you identify a Technique used in a breach, you write its ID (like T1078) so any security professional in the world immediately knows exactly what happened.

// THE COLONIAL PIPELINE ATTACK — STEP BY STEP
Before you map techniques, understand the story. Read each step, then on the next tab you'll match each step to the correct ATT&CK technique. This is how real SOC analysts and incident responders work — they reconstruct the timeline first, then classify it using the framework.
1
Dark Web Credential Discovery
Months or years before the attack, an employee's credentials were compromised in an unrelated breach and appeared on the dark web. DarkSide affiliates (or brokers who sell access) searched for valid credentials targeting Colonial Pipeline's VPN login portal.
Passive reconnaissanceCredential theft from prior breachNo dark web monitoring in place
2
VPN Login with Stolen Password
On May 7, 2021, attackers used the stolen VPN password to authenticate directly into Colonial Pipeline's network. There was NO multi-factor authentication on the VPN — a single password was all that stood between the public internet and the internal network.
T1078 — Valid AccountsT1133 — External Remote ServicesNo MFA = direct access
3
Lateral Movement Through the IT Network
Once inside the VPN, attackers moved laterally through Colonial's IT network. There was no segmentation to stop them. They mapped the environment, identified critical systems, and positioned themselves to deploy ransomware at maximum impact.
T1021 — Remote ServicesNo network segmentationDwell time: hours
4
Data Exfiltration — 100GB Stolen
Before deploying ransomware, DarkSide exfiltrated approximately 100GB of sensitive data. This is "double extortion" — they now had leverage beyond encryption: "Pay us or we publish your data." The exfiltration happened over alternative protocols to avoid detection.
T1048 — Exfiltration Over Alt ProtocolDouble extortion strategyNo DLP controls detected this
5
Shadow Copy Deletion
Before encrypting files, DarkSide deleted Windows Shadow Copies (automatic backup snapshots) and disabled backup services. This made recovery impossible without either the decryption key or an offline backup — forcing Colonial to choose: pay or lose everything.
T1490 — Inhibit System RecoveryBackup deletion = no free recovery
6
DarkSide Ransomware Deployed
DarkSide ransomware encrypted files across Colonial's IT systems. Each encrypted file received a unique extension. A ransom note appeared demanding payment in Bitcoin. Colonial's IT systems were rendered inaccessible within minutes of deployment.
T1486 — Data Encrypted for ImpactRansom demand: $4.4M Bitcoin
7
Pipeline Shutdown — National Emergency
Colonial Pipeline proactively shut down 5,500 miles of pipeline to prevent the ransomware from potentially spreading to OT (operational technology) systems. This decision — while cautious — caused fuel shortages across 17 states. President Biden declared a national emergency.
T1489 — Service Stop17 states affectedNational emergency declared
// CONFIRMED ATT&CK TECHNIQUES — COLONIAL PIPELINE
These are the 6 confirmed MITRE ATT&CK techniques documented in the Colonial Pipeline incident. For each one: read the technique ID and name, understand how it was used specifically, and note the defensive opportunity that was missed. Use these as your reference when completing the Student Worksheet.
T1078
Valid Accounts
TACTIC: Initial Access · Persistence
How used in this incident
Attackers used a legitimate employee VPN credential found on the dark web. Because the credential was valid, no security alert was triggered — the system saw a normal login.
Why it worked
No MFA on the VPN. A single username + password = full network access. The credential had been exposed in a prior unrelated breach and was never rotated.
Defensive opportunity missed
MFA would have stopped this cold. Dark web monitoring would have flagged the exposed credential. Password rotation policies would have invalidated it.
↗ View T1078 on ATT&CK
T1133
External Remote Services
TACTIC: Initial Access · Persistence
How used in this incident
Colonial's VPN was an external remote access service exposed to the internet. DarkSide used it as the entry point — it was the only door they needed, and it was unlocked.
Why it worked
External remote services are necessary for business operations, but they are high-value targets. Without MFA and proper monitoring, a VPN is a front door left open.
Defensive opportunity missed
VPN login monitoring for unusual times/locations, MFA, IP allowlisting for known employee locations, and rate limiting on authentication attempts.
↗ View T1133 on ATT&CK
T1021
Remote Services — Lateral Movement
TACTIC: Lateral Movement
How used in this incident
Once inside the VPN, attackers used remote service protocols (RDP, SMB, or similar) to move laterally from system to system within Colonial's IT network, mapping the environment before deploying ransomware.
Why it worked
No network segmentation. The IT network was flat — once inside the VPN, every system was reachable. There were no internal chokepoints to require re-authentication.
Defensive opportunity missed
Network segmentation, zero-trust architecture, and behavioral analytics (detecting unusual lateral movement patterns) would have flagged or stopped this.
↗ View T1021 on ATT&CK
T1048
Exfiltration Over Alternative Protocol
TACTIC: Exfiltration
How used in this incident
Before deploying ransomware, DarkSide exfiltrated approximately 100GB of sensitive data using protocols that blended with normal traffic to avoid detection. This enabled double extortion.
Why it worked
No Data Loss Prevention (DLP) solution was monitoring outbound data transfers for unusual volume or destination. 100GB leaving the network went undetected.
Defensive opportunity missed
DLP tools monitoring outbound traffic volume, UEBA (User Entity Behavior Analytics) detecting anomalous data transfers, and SSL inspection of egress traffic.
↗ View T1048 on ATT&CK
T1490
Inhibit System Recovery
TACTIC: Defense Evasion · Impact
How used in this incident
DarkSide deleted Windows Volume Shadow Copies (VSS) — the automatic backup snapshots Windows creates. They also disabled backup services, eliminating the ability to recover files without paying.
Why it worked
Shadow copies were accessible from within the compromised network. No immutable or air-gapped backups existed that DarkSide couldn't reach and delete.
Defensive opportunity missed
Offline air-gapped backups (ransomware cannot encrypt what it cannot reach). Protected shadow copies using VSS ACLs. File integrity monitoring to detect VSS deletion.
↗ View T1490 on ATT&CK
T1486
Data Encrypted for Impact
TACTIC: Impact
How used in this incident
DarkSide ransomware encrypted files across Colonial's IT systems using strong encryption (RSA + Salsa20). Each victim received a unique decryption key held by DarkSide — pay or lose your data permanently.
Why it worked
By the time ransomware deployed, every defensive opportunity had already been missed (no MFA, no segmentation, no DLP, no offline backups). Ransomware was the final blow after the network was already owned.
Defensive opportunity missed
Endpoint Detection and Response (EDR) with behavioral analysis can detect and kill ransomware encryption processes in real time. Application whitelisting prevents unauthorized executables.
↗ View T1486 on ATT&CK
T1489
Service Stop
TACTIC: Impact
How used in this incident
Colonial Pipeline voluntarily stopped all pipeline operations to prevent ransomware from potentially spreading to OT (operational technology / industrial control) systems. The attacker's ransomware on IT systems indirectly caused the OT shutdown.
Why it worked
The IT and OT networks were not fully isolated. Colonial could not be confident the ransomware had not already reached or could not reach the pipeline control systems — so they shut everything down.
Defensive opportunity missed
Complete IT/OT network separation (air gap). OT systems should have no path to IT-facing networks. Had this been in place, Colonial could have kept the pipeline running during the IT incident.

How it was used in Colonial Pipeline

One defensive mitigation
Enforce Multi-Factor Authentication (MFA) on all remote access systems. A stolen password alone is useless if a second factor (authenticator app, hardware key) is also required.
